## 5.1 自定义基于 PyTorch 的 CPU 算子

### 实验目的

掌握如何在 PyTorch 中新增自定义 `mysigmoid` 算子：

1. 熟悉 PyTorch 整体设计机理。
2. 通过 C++ 扩展在 PyTorch 中添加自定义 CPU 算子，加深对 PyTorch 算子实现机制的理解。
3. 为后续添加自定义 DLP 算子奠定基础。

实验工作量约 50 行代码，约需 2.5 小时。

### 背景介绍

`mysigmoid` 参照 Sigmoid 激活函数实现，计算公式为：

```text
mysigmoid(x) = 1 / (1 + exp(-x))
```

在 PyTorch 中添加新算子主要有三类方式：

1. 基于原生 PyTorch 修改源码：便于和原生算子融合，但与 PyTorch 源码耦合高，新增或修改后需要重新编译 PyTorch。
2. 基于 C++ 扩展：与 PyTorch 源码解耦，可以通过扩展模块生成动态库供 Python 调用。
3. 基于 OP Register：同样与 PyTorch 解耦，适合按注册机制扩展算子。

本实验采用 C++ 扩展方式，流程包括 C++ 实现、算子编译、算子测试。

### 实验环境

硬件平台：MLU 云平台环境，本实验只使用 CPU。

软件环境：PyTorch、Python 3，以及 Pillow、Numpy、Scipy 等扩展库。

### 实验内容

基于实时风格迁移推理实验，将网络中的 Sigmoid 算子替换为自定义 `mysigmoid` 算子。主要流程如下：

1. C++ 实现：编写 `mysigmoid.cpp`，实现 `mysigmoid_cpu` 核函数并通过 `pybind11` 绑定到 Python 模块。
2. 算子编译：编写 `setup.py`，通过 Setuptools 和 `torch.utils.cpp_extension` 编译动态链接库。
3. 算子测试：编写测试脚本，导入动态库并验证 `mysigmoid_cpu` 输出形状和数值。
4. 网络修改：在实时风格迁移网络中导入自定义动态链接库，在 `TransNet.forward` 中调用 `mysigmoid`。
5. 推理测试：运行 CPU 推理脚本，查看输出目录中的推理结果。

### 实验步骤

1. 补全 `5-1/mysigmoid.cpp`：
   - 引入 `torch/extension.h`。
   - 将输入 Tensor 展平成浮点向量。
   - 对每个元素计算 `1 / (1 + exp(-x))`。
   - 将结果转换回 Tensor，并恢复输入形状。
   - 使用 `PYBIND11_MODULE` 绑定 `mysigmoid_cpu`。

2. 补全 `5-1/setup.py`：
   - 配置动态库名称 `mysigmoid_extension`。
   - 指定编译文件 `mysigmoid.cpp`。
   - 配置 `BuildExtension` 编译命令。

3. 编译算子：

```bash
cd 5-1
python setup.py build_ext --inplace
```

4. 测试算子：

```bash
python test_mysigmoid.py
```

5. 修改并运行实时风格迁移推理：

```bash
python evluate_cpu.py
```

推理结果输出到 `../out/cpu/`。

2. 80 分：在 60 分基础上，补全算子测试程序，能够正确调用 `mysigmoid` 算子。
3. 100 分：在 80 分基础上，修改网络结构，正确使用 `mysigmoid` 完成实时风格迁移推理。

### 实验思考

1. 框架内部核心代码为何采用 C/C++，而不是 Python 等高级语言？

## 5.2 Transformer 架构实现与应用

### 实验目的

掌握 Transformer 模型的核心原理与 PyTorch 实现方法。通过模块化编程、模型搭建与推理评估，深入理解 Transformer 的工作机制，并具备在 PyTorch 中实现复杂深度学习模型的能力。

具体包括：

1. 理解 Transformer 的整体架构，包括编码器-解码器结构及其关键组件。
2. 掌握位置编码、多头注意力、前馈神经网络等核心模块的原理与实现。
3. 熟悉在 PyTorch 中完成 Transformer 模型搭建与推理的流程。
4. 能够在 DLP 上完成翻译任务的性能验证，并具备基础模型分析能力。

实验工作量约 90 行代码，约需 4 小时。

### 背景介绍

机器翻译用于将源语言自动转换为目标语言。早期神经机器翻译主要采用 Seq2Seq 编码器-解码器结构。Transformer 使用自注意力机制替代传统 RNN/CNN 序列建模方式，具有并行计算效率高、长距离依赖建模能力强等特点。

Transformer 基本组件包括：

1. 词嵌入模块：将词索引映射为高维稠密向量，支持零填充和按嵌入维度平方根缩放。
2. 层归一化模块：对每个样本最后一个维度进行归一化，并使用可训练参数 `gamma` 和 `beta` 做缩放平移。
3. 位置编码模块：使用正弦和余弦函数生成序列位置信息。
4. 多头注意力模块：对 Q、K、V 做线性投影，执行缩放点积注意力，多头拼接后做残差连接和层归一化。
5. 前馈神经网络模块：两层线性变换，中间使用 ReLU，并带残差连接和层归一化。
6. 标签平滑模块：将 one-hot 标签转换为平滑概率分布，降低模型过度自信。

### 实验环境

硬件平台：MLU 云平台环境。

软件环境：PyTorch、CNNL、CNToolkit、Python 3 及相关扩展库。

数据集：IWSLT2016 机器翻译数据集。该数据集包含平行语料，可用于 Transformer 等神经机器翻译模型的训练与性能评估，常用 BLEU 指标衡量翻译质量。

### 实验内容

1. 实现 Transformer 基本单元模块：词嵌入、层归一化、位置编码、多头注意力、前馈神经网络、标签平滑。
2. 基于基本单元模块搭建编码器-解码器 Transformer 翻译模型，并构建损失函数。
3. 实现 Transformer 模型推理与 BLEU 评估流程。

### 实验步骤

1. 补全 `5-2/modules.py`：
   - `embedding`：实现 Xavier 初始化、零填充、`F.embedding` 查表和缩放。
   - `layer_normalization`：实现最后一维均值、标准差、归一化和可训练缩放平移。
   - `positional_encoding`：按 Transformer 论文公式生成正弦位置编码。
   - `multihead_attention`：实现 Q/K/V 投影、多头拆分、缩放点积注意力、mask、dropout、残差连接和层归一化。
   - `feedforward`：实现两层逐位置前馈网络、残差连接和层归一化。
   - `label_smoothing`：实现平滑标签分布。

2. 补全 `5-2/AttModel.py`：
   - 构建编码器和解码器的 embedding、位置编码、dropout、多头注意力、前馈网络。
   - 在前向传播中构建 decoder 输入，完成编码器和解码器计算。
   - 输出词表概率、预测索引、准确率和平均损失。

3. 补全 `5-2/eval.py`：
   - 加载德语和英语词表。
   - 初始化 `AttModel` 并加载预训练权重。
   - 构建 `TestDataSet` 和 `DataLoader`。
   - 执行自回归推理，将翻译结果写入日志。
   - 计算推理时间、吞吐率和 BLEU 分数。

4. 运行实验：

```bash
cd 5-2
python eval.py --device CPU
```

如需在 MLU/DLP 环境运行，使用 PDF 对应环境中的运行脚本，例如：

```bash
bash run_transformer_cpu.sh
bash run_transformer_mlu.sh
```

2. 80 分：在 60 分基础上，正确实现 Transformer 翻译模型构建。
3. 90 分：在 80 分基础上，正确实现 Transformer 翻译模型评估模块。

### 实验思考

1. 为什么 Transformer 完全摒弃 CNN 和 RNN 结构？相比它们有什么本质优势？
2. 多头注意力机制为何设计为并行的多个注意力头，而不是扩展维度形成一个更大的单一注意力？不同注意力头在表达能力上分别起到什么作用？
3. Transformer 在计算注意力时，为什么要在 Softmax 之前除以 `sqrt(d)`？
4. Transformer 最初用于自然语言处理，后来成功应用到视觉、音频、图数据等领域。Transformer 为何具有较强的跨模态迁移能力？
5. Transformer 的运行有哪些核心瓶颈？在计算、存储和推理效率上分别存在什么挑战？
